## OpenClaw / Cloudflare 环境经验
- OpenClaw 2026.8.2 在当前 explicit-ownership 多 Agent 配置下将 `main` 的工作区解析为 `~/.openclaw/workspace/main`。已将原 `~/.openclaw/workspace/` 中除目标 `main/` 外的全部内容（包含 `projects/` 与历史 `.git`）迁入 `workspace/main/`；旧根现在只剩 `main/`。`main` 和 `browser-sandbox` 的 workspace 均已显式固定到该路径，迁移前由 8.2 新建的空仓库/默认模板保存在 `~/.openclaw/backups/workspace-main-migration-20260903-1308/preexisting-main/`。
- `~/.openclaw/.env` 不会覆盖 Gateway 进程中已存在的同名环境变量。Linux systemd unit 会先读取 `~/.openclaw/gateway.systemd.env`，因此仅修改 `.env` 后执行 `gateway restart` 可能继续沿用旧快照。
- 本次通过 `env -u CLOUDFLARE_API_TOKEN -u CLOUDFLARE_ACCOUNT_ID openclaw gateway install --force` 重新生成服务环境，再重启 Gateway，已确认进程 Token 指纹与 `.env` 一致并经 Cloudflare verify 为 Active。
- Cloudflare D1、R2 已启用并可用；不要在日志、命令参数、聊天或记忆中记录任何 Token、AK/SK、管理员密码等秘密。
